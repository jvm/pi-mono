# Pi 1.6.0 extension compatibility audit

**2026-11-24 · `jvm/pi-mono` at `a916305` · 14 published extensions**

Move the development baseline to **1.6.0**, but not as a dependency-only change. Fix `pi-skillful`'s editor rendering, transfer ownership of Codex effort updates to Pi, and classify the new Fast models. Eleven package suites already pass unchanged. The red shared prompt tests do **not** show that Scout or Skillful overrides the user's prompt.

## What needs to change

### 1. `pi-skillful`: copy before decorating editor output

[Pi TUI's breaking change](https://github.com/earendil-works/pi/blob/v1.6.0/packages/tui/CHANGELOG.md): `Component.render()` returns `readonly string[]`. `Container` can return the **same array** until a child changes. In [`session-skill-toggles.ts`](../../packages/pi-skillful/src/extensions/session-skill-toggles.ts), both `SkillToggleEditor.render` (line 216) and `SkillToggleEditorWrapper.render` (314) overwrite `lines[0]` on an array they do not own. The wrapper fails with TS4104/TS2542. Running through Pi's TS loader without type-checking does not make the mutation safe: another editor can return a cached or frozen frame.

Copy both results (`[...super.render(width)]`, `[...this.inner.render(width)]`) before replacing the border. **Verified in isolation:** these two changes alone made the check and all **27** Skillful tests pass. Add a composed-editor test that returns the same frozen frame twice and checks both the decorated output and the untouched child. Smoke the private startup `[Skills]` coloring, toggle border, theme and reload in regular and fullscreen TUI before release. Other direct consumers inspected, including the process manager and Skillful settings list, spread child rows into their own arrays; they do not need a blanket copy.

### 2. `pi-openai-reasoning`: deprecate the workaround on native hosts

The [released Codex serializer](https://github.com/earendil-works/pi/blob/v1.6.0/packages/ai/src/api/openai-codex-responses.ts) now **honors `compat.supportsMidConvoEffort`**. The opposite claim in [`reasoning.ts`](../../packages/pi-openai-reasoning/src/reasoning.ts) is obsolete. On supported models Pi emits `configuration_update` itself, with request-level effort `medium`; the extension's existing guard returns early on a native update. That is why users need not lose thinking controls even though **12 of 23** package tests fail. They assert the old first-effort baseline, update positions, off behavior or custom state history. Do not fix them by stripping Pi's native items.

With mocked transport, compared two-turn `low → high` runs **with and without** the extensions on both Codex 6.2 models. Each had `medium` plus `[low]`, then `medium` plus `[low, high]`; neither wrote a `pi-openai-reasoning:v1` entry. This establishes request behavior, **not** server-side reasoning quality or cache savings. Both models disallow wire effort `none`/`minimal`; the Codex catalog maps the UI's `minimal` to `low` and disables `off`.

Recommend a documented no-op on native hosts, leaving old session entries readable/ignorable. Gate ownership by host support, not just the presence of an update in the *current request*: upstream `main` can omit it on the first turn. Keep a fallback only if intentionally retaining older-host behavior; explicit opt-out, unknown providers, virtual selections and disallowed modes must remain untouched. Test stock vs installed, prompt → level switch → retry → resume/fork → compaction, and assert identical requests and no new custom state on the native path. Do not unpublish or remove the package as part of the baseline bump.

### 3. `pi-fast`: the default model is shown as unavailable

Pi changed the default on `openai`, `openai-codex` and `azure` to `gpt-6.2-sol`. [`OPENAI_FAST_MODELS`](../../packages/pi-fast/src/fast-mode.ts) lacks both `gpt-6.2-sol` and `gpt-6.2-astra`. `/fast on` therefore cannot enable either on the package's **two supported providers**. This is a feature gap, not a provider rejection. The catalog-coverage test also flags **`openai/gpt-6-cyber`**; adding only the two model IDs does not make it pass.

The [pinned Codex catalog](https://github.com/openai/codex/blob/7ce4437488c69950fe87f1d8ab4b00bdb4bbd193/codex-rs/models-manager/models.json) advertises `priority`/Fast for both 6.2 models. [OpenAI's API Fast guide](https://developers.openai.com/api/docs/guides/fast-mode) documents both and shows `service_tier: "fast"` on Sol. Neither source established Fast for `gpt-6-cyber`; leave it disabled unless documented. Preserve opt-in, `fast` for API keys, `priority` for subscriptions, and no Azure/virtual inference by name. Do not silently opt users into Ultrafast.

**Verified in isolation:** adding both supported IDs and classifying Cyber as non-enabled made all **43** Fast tests pass. Substituting 6.2 Sol for the default public-model fixture in `automatic.test.mjs` gave 62/65 before that allowlist change and **65/65** after it. Add explicit 6.2 API-key/OAuth tier assertions to the permanent suite. The upstream advertisement does not guarantee the tier an account will receive.

### 4. Change six shared expectations, not the features they protect

- Four cases in [`structured-prompts.test.mjs:275`](../../tests/structured-prompts.test.mjs) still get exactly `"Exact fixture policy."` but fail at line 284, which requires zero system/developer input items. The Codex serializer now places the initial system prompt in the **first developer input item**, not top-level `instructions`, to preserve the prefix cache. Assert one effective policy and no Scout/skill deltas or duplicates across turns and load orders. Do not remove the precedence test.
- Two Codex-target cases in [`virtual-models.test.mjs:47`](../../tests/virtual-models.test.mjs) assume *no* `configuration_update` means the extension did not act. The physical provider now emits its own even when the extension sees only a virtual identity. Compare with an extension-free route and check that no extension state, Fast tier, grammar tool or automatic compaction leaked. Do not grant virtual models physical-model capabilities.
- The seventh root failure is intentional: [`pi-baseline.test.mjs`](../../tests/pi-baseline.test.mjs) asserts the exact 1.5.2 pin. Move it with [`test-pi-compat.mjs`](../../scripts/test-pi-compat.mjs), the workspace manifests/dev lock, CI job label, root guidance and current-baseline docs. Keep the single-host policy and runtime peer ranges. Pi's declared Node floor is still `>=22.19.0`. This upgrade also takes the resolved host `undici` from 8.12.3 to **8.12.4**, the security update noted in the [release changelog](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/CHANGELOG.md); changing dev pins alone does not patch a user's installed Pi.

## Deprecations and changes that do *not* require migrations here

- For the four Oct 30 releases, Pi 1.5 moved tool validation to `pi-schema`: TypeBox-only refinements, non-JSON types and custom formats no longer validate tool arguments. No affected production schema using those features was found. The repo already adapted its typed string-enum helpers at `4932bd1`. Keep runtime input checks. Pi 1.5 also deprecated `GrepOperations.readFile` for context lines; no extension implements this hook. No dependency found on an explicit `tools: []` for a disabled loadout.
- Pi 1.5 reads an extension's root `CHANGELOG.md` by default, so all 14 already have the update-notice mechanism. Pi 1.5's `pi.exec` bounds and render-context keybinding helpers are already used by Scout and Codex Tools. The 1.5.2 missing-cwd fork flow is worth covering for cwd-scoped settings; resolve trust and paths from the replacement session, not the original folder.
- Pi 1.6 removed `mapStopReasonString` from the Google shared AI subpath and two retired Qwen Team model IDs. No production import or hard-coded selection found in these extensions. No new blanket deprecation of the public extension event/tool registration API was found. `find` slash patterns now match relative to the search directory (`**/src/*.ts` for any depth); no extension replaces the built-in find executor.
- `@earendil-works/pi-ai/session-resources` releases **provider-session** resources, e.g. a provider WebSocket. It does not replace extension `session_shutdown` handling for child processes, monitors or files. SDK `AgentSessionRuntime.takeUnreportedDiagnostics()` is useful for host integration fixtures after session replacement; it is not an `ExtensionContext` method.
